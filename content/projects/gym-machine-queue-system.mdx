## Project Overview

Gym equipment at busy recreation centers often turns into a waiting game: people hover near machines unsure when they'll be free, there's no clear visibility into wait times, and no practical way to plan or reserve equipment in advance.

This system addresses that by adding a lightweight queue management layer directly onto each machine. Every piece of equipment is paired with a Heltec V3 board acting as the local controller, and an nRF loop antenna that enables simple NFC-based check-in. A second Heltec unit acts as the server, running a minimal web interface over a local WiFi network.

When a user taps their phone to the antenna, a browser page automatically opens (e.g. `machine1.local`). From there, they enter their name or ID and specify workout parameters like sets, reps, or duration before joining the queue. The goal is a no-app, hardware-light system that turns unstructured gym congestion into a coordinated, transparent experience.

## Objectives

- Eliminate passive hovering and uncertainty around gym equipment availability
- Enable queue join via NFC tap with zero app installation required
- Provide a live browser-based dashboard showing position, wait time, and equipment status
- Display session state clearly on an embedded OLED with physical button confirmation
- Log session data including duration, completion status, and timestamp to flash storage

## System Architecture

The system is split across two Heltec V3 ESP32 boards:

- **Server Heltec**: hosts the web server over local WiFi, manages the queue, serves the dashboard, and handles all session state logic
- **Client Heltec**: mounted on the machine, drives the OLED display, reads the physical confirm button, and communicates session state to the server over WiFi

An nRF loop antenna connected to the client unit acts as a stand-in for an NFC sticker. When a user taps their phone, the phone opens `http://machine1.local/queue` automatically, no app, no pairing required.

## How It Works: UX Flow

### 1. Join the Queue

The user taps their phone on the nRF loop antenna. Their browser automatically opens `http://machine1.local/queue`, a web server hosted by the server Heltec. The user enters their name or student ID, inputs their desired sets, reps, or miles, and joins the queue, all from their phone.

### 2. Queue View

The dashboard shows the user their current place in line, an estimated wait time based on the sets queued ahead of them, and which equipment is open or taken. The view updates live as the queue changes. Queue length in both people and time is displayed on the board, along with time remaining on the current active session.

### 3. Session Starts

When it's the user's turn, the dashboard notifies them on their phone. They walk up to the machine and press the physical confirm button on the Client Heltec to begin their session. The timer starts immediately.

### 4. Session Runs

The timer counts down on the Heltec OLED. The display shows the current user, time remaining, and queue length. Live updates are pushed to the dashboard over WiFi continuously throughout the session.

### 5. Session Ends

There are two ways a session can end:

- **Timer hits zero**: ends automatically
- **User presses the confirm button**: ends immediately, marked as ended early

Either way, the next person in queue is promoted and the Heltec logs the session summary, duration, completion status, and timestamp, to flash storage.

## OLED Display States

The client Heltec OLED cycles through four defined states depending on machine status:

### Idle:
Machine is free and waiting for a user. The display shows a ready prompt and instructs the next person to tap their phone to join.

### Waiting:
The user is next in queue. The display shows their name and prompts them to press the physical button to begin their session.

### Active:
A session is in progress. The display shows a large countdown timer, the current queue length, and an option to end the session early via the confirm button.

### Ended:
The session has finished. The display briefly shows either `TIME'S UP!` or `ENDED EARLY` alongside a thank-you message with the user's name before returning to idle.

## Key Technical Work

### 1. NFC-Based Tap-to-Join

Used an nRF loop antenna as a stand-in for a commercial NFC sticker. When a phone taps the antenna, it triggers the phone's browser to open the machine's local URL automatically, no app install, no Bluetooth pairing, no QR scan required.

### 2. Embedded Web Server

The server Heltec runs a lightweight HTTP web server over local WiFi. It serves the queue join form and live dashboard, handles form submissions, manages queue state, and pushes live updates to connected clients, all from an ESP32.

### 3. Live Dashboard

The browser-based dashboard updates in real time as queue state changes. Users can see their position, estimated wait, and equipment availability without refreshing the page. This was implemented using WiFi-based push updates from the server Heltec.

### 4. Physical Button Confirmation

A physical tactile button on the Client Heltec serves as the session confirm and early-end control. This keeps the interaction grounded in hardware: the user must be physically present at the machine to start or end a session, preventing remote queue manipulation.

### 5. Flash Storage Logging

At the end of every session, the system writes a structured log entry to the Heltec's onboard flash storage. Each entry includes session duration, whether the session was completed fully or ended early, and a timestamp. This lays the groundwork for broader gym-wide analytics.

### 6. Inter-Device WiFi Communication

The client and server Heltec units communicate continuously over WiFi. Session state, timer data, queue length, and OLED display content are all kept in sync between the two boards in real time.

## Looking Ahead

The system is designed to scale into a full facility-wide coordination platform:

- **Centralized gym dashboard**: a real-time overview of all machines showing queue lengths, estimated availability, and utilization across the entire space, helping users make informed decisions before walking to a machine
- **Personal workout tracking**: each session could automatically sync to a user's profile, building a structured workout history including completed sets, timing, and equipment usage frequency
- **Personalized recommendations**: over time, session data could support workout planning, progress tracking, and usage-based suggestions
